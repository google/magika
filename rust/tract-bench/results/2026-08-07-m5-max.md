# Apple M5 Max feasibility result

Date: 2026-08-07

## Environment

- Magika base commit: `94ffd1d`
- Host: Apple M5 Max, 18 cores, 128 GB memory
- OS: macOS 26.5.2 (25F84), arm64
- Rust: rustc 1.95.0, cargo 1.95.0
- ONNX Runtime: `ort 2.0.0-rc.12`
- tract: exact version `0.23.4`
- Build: release, one codegen unit, LTO, stripped
- Input: batch 1, features extracted from `README.md`

The CPU comparison below is the median of six 200-iteration trials. Backend order alternated
between trials with `--reverse`. Times are microseconds. Cold time is model load plus runtime
preparation; first is the first inference after preparation; the remaining columns follow ten
unreported warmups.

## Correctness

| Comparison | Maximum absolute score difference | Winning labels |
| --- | ---: | --- |
| ONNX Runtime vs tract CPU | 2.4883775e-9 | identical |
| tract CPU vs tract Metal | 2.3841858e-7 | identical |

The harness checks every row and fails if a winning label differs or any score differs by more
than `1e-4`.

## Artifact and executable footprint

| Artifact | Bytes | Change from current |
| --- | ---: | ---: |
| ONNX model | 3,163,737 | baseline |
| NNEF/tract-OPL model | 2,918,110 | -7.76% |
| ONNX Runtime-only benchmark executable | 19,776,896 | baseline |
| tract CPU-only benchmark executable | 15,989,376 | -19.15% |
| tract CPU + Metal benchmark executable | 18,028,032 | -8.84% |

Each executable embeds its model. The runtime-specific harness code and release profile are the
same. `otool -L` shows no separately shipped ONNX Runtime dylib in this configuration. The Metal
build adds 12.75% over tract CPU and links the system Metal framework.

Metal in each trial, so treat small differences as directional rather than conclusive.

| Backend | Cold | First | Mean | p50 | p95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| tract CPU | 19,979 | 2,611 | 2,394 | 2,314 | 2,736 |

Metal does not meet the 15% warm improvement threshold for batch 1. It also adds 2,038,656 bytes
to the tract CPU executable and greatly increases cold preparation.

## Conversion and integration blockers

- The deterministic NNEF archive loads with `tract-core` extensions only; it does not need the
  ONNX parser or ONNX-only tract-OPL registry at runtime.
- Keeping the ONNX model's symbolic batch dimension fails tract 0.23.4 graph resolution at the
  one-hot `BroadcastTo` because the shape is considered variable-rank. The benchmark artifact is
  specialized to `[1, 2048]`.
- Because of that specialization, this result does not measure realistic multi-file CLI batches,
  the workload most likely to amortize Metal preparation and transfers.
- `tract-metal` pulls `tract-gpu`, `tract-transformers`, and `tract-pulse-opl`, which explains much
  of the optional backend's footprint cost.

## Recommendation

Do not replace ONNX Runtime or enable Metal by default on the current evidence. The numerical
parity is excellent and a 19% smaller CPU binary is promising, but CPU latency, size reduction,
and dynamic-batch support do not jointly clear the spike thresholds. If the exploration continues,
the next bounded task should be to remove or rewrite the ONNX dynamic shape subgraph so tract can
serialize one dynamic-batch NNEF model, then re-run CPU and Metal on representative CLI batches.
